# Loop Engineering 面试追问清单

## 1. 为什么用 LangGraph，而不是在函数里顺序调用？

Loop 需要明确的节点状态、条件分支、暂停恢复和 checkpoint。StateGraph 把这些运行时状态变成图的一部分，避免用隐式函数调用堆叠控制流。

## 2. checkpoint 保存什么？

保存可序列化的 graph 状态、节点写入和 checkpoint 元数据。业务事实仍写入项目、运行、证据、发现、风险和报告等业务表，checkpoint 只负责恢复执行。

## 3. interrupt 怎么工作？

某个节点判断缺少必要输入时调用 `interrupt`，运行进入暂停状态。用户提交回答后，用同一个 `thread_id` 恢复，重新构建上下文再继续执行。

## 4. worker 如何避免重复领取任务？

worker 用 `SELECT ... FOR UPDATE SKIP LOCKED` 领取 queued job，同时写入 lease、heartbeat 和下一次可见时间。其他 worker 跳过已锁定行，过期租约由恢复流程重新排队。

## 5. 为什么 MySQL DATETIME 会导致任务卡住？

MySQL DATETIME 默认按秒存储。带微秒的时间写入时可能被四舍五入到未来一秒，查询条件把它当成尚未到期的任务。项目统一按整秒写入，并让接口等待运行真正结束。

## 6. 为什么强调确定性 verifier？

LLM 输出可能不稳定，不能直接决定任务是否完成。结构完整性、证据引用、代码覆盖和风险缓解先由确定性规则检查；LLM 只提供建议，不覆盖阻塞性错误。

## 7. 8 个评估用例是什么？

3 个是确定性扫描回归，5 个是五类调研档位的合成 fixture。它们验证报告结构、档位检查、证据引用和质量元数据，不等同于真实仓库上的人工质量评测。

## 8. 自调研报告是怎么产生的？

把本项目登记为本地目录输入源，后台 Loop 执行 9 个节点，生成约 1.6 万字报告，9 项确定性校验通过。扫描时包含依赖和构建目录，因此报告中的文件数不能当作纯源码规模。

## 9. 目前最大的不足是什么？

缺少公开、真实、多仓库的人工质量评测集；外部 LLM 在本地演示中曾因 401 失败，但确定性降级链路正常。下一步应补充真实仓库样本、人工评分和 LLM 可用性回归。
